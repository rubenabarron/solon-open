# Build log 0005: the site repositions to the open work

Date: 2026-10-02 | Status: published

## What shipped

solonai.org was reworked in place from a single-purpose pilot funnel into the
developer-facing site for Solon. The new `/open/` page explains what is public and what
stays internal, and links this repository. The former `/pilot/` page became
`/design-partners/`, and the old URLs redirect there with a 301. The homepage now leads
with the loop and the demonstration, with "Built in the open" and "Work with us" sections
below it. Every content page carries the same pair of calls to action: see the demo, or
read the open work.

The machine layer moved with the copy. The site description, the FAQ, the machine facts
for AI crawlers, the sitemap, and the organization schema all describe the open work and
the design-partner path.

## The claim boundary

The site's claim is "built in the open". It points at the public thinking here, not at
installable code. The code repository stays private for now, and when it opens, its
license will be stated there before the site says anything more. The wording rule is
mechanical, not editorial: the site check fails the build if the site overstates what is
public.

## The naming caveat

The site carries one public identity, Solon, and nothing more. The company and platform
name is not on the site while it is still being settled, so the site will not have to
change when that decision lands.

## How it was verified

- The local battery: type check, 33 tests, a clean static export, a 114-check site audit,
  a contrast check, and a local redirect check for the retired URL.
- 36 screenshots across nine pages, desktop and mobile, light and dark, reviewed against
  an anti-pattern checklist.
- Preview deployment checked at 114 checks; production checked at 118 (the extra four are
  redirect checks that run only in production: two for the www host and two for the
  retired pilot URL).
- Search engines notified: IndexNow accepted all 9 URLs (HTTP 200).
- The retired URL returns a 301 to the new page on production, verified directly.

## What we learned

- A page rename is a migration, not a rename. The 301 path, the sitemap, the machine
  facts, and the search notification all had to move together, and the check suite now
  pins the redirect so a future cleanup cannot quietly drop it.
- Claim discipline is checkable. The rule "do not say more than is public" became a
  mechanical guard over the built site, which is stronger than a note in a style guide.
- Publish the positioning after it ships, not before. This entry describes the live site,
  with the deployment and its verification named.
