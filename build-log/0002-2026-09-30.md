# Build log 0002: the open work repository launches

Date: 2026-09-30 | Status: published

## What shipped

The first wave of this repository: the publishing boundary and gate (PUBLISHING.md and the
mechanical gate script with its tests), curated product principles, a curated architecture
overview, decision entry 1 (why this repository exists), and build log 0001. The
repository was staged privately, reviewed file by file at a human gate, then published
through a pull request the human merged.

## How it was verified

- The mechanical gate reports the repository clean, and its six tests pass.
- Every artifact was reviewed against its brief before publication, and the human reviewed
  the staged tree before the repository was created.
- A post-publication audit swept for private keys and internal information. It found one
  real issue: the gate script listed its guarded names verbatim, contradicting the
  boundary it enforces. The fix followed the same rule as everything else: a branch, a
  reviewed diff, a human merge.

## What we learned

- Rulebooks need to obey their own rules. The one finding came from the file that enforces
  a rule it was itself breaking. The gate now assembles its guarded names from fragments.
- A staged tree plus a human gate catches what a script cannot: judgment cases, wording,
  and the plain question of whether something should be public at all.
- Git history is part of the publication. Fix-forward keeps the record honest, and the
  older content stays reachable in history, which is a decision to make knowingly.
