# Build log 0004: the acceptance demo becomes calibration-ready

Date: 2026-10-01 | Status: published

## What shipped

The end-to-end acceptance demo can now run against any policy checkout instead of only
this repository. It honors the policy directory and the git remote from the environment,
performs its fetch and its simulated merge inside the configured checkout, and keeps the
defaults identical so nothing changes for the standard runs.

Why it matters: the go-live calibration before a pilot runs the whole loop (five
escalations, three overrides, a proposed policy update, a human merge, then a sixth
request that auto-approves) against the customer's own policy repository. That path is
now a configuration flag, not a fork of the harness.

## How it was verified

- Seven new unit tests pin the resolution and the mode behavior; the full suite is 214
  passed plus one environment-dependent skip.
- The standard no-token run passes 9 of 9, and a run pointed at a scratch clone also
  passes 9 of 9, with the simulated merge landing in the clone while the main checkout
  stays pristine.
- The website checks and the five-job CI pipeline are green.

## What we learned

- The harness caught its own regression. The first cut let a local `.env` value win over
  the forced working-tree read, so the final auto-approve check failed (8 of 9). A
  one-line semantics change, invisible in code review, was caught only by running the
  real end-to-end path. Keep the acceptance run in the loop even for small changes.
- A fresh checkout needs a git identity before the simulation can commit. The dry run
  surfaced it, and the deployment runbook now carries the note.
